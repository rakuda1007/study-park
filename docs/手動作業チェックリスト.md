# 手動作業チェックリスト（study-park）

リポジトリの雛形作成後、**あなたが手元で行う作業**をまとめています。順不同の項目もありますが、初回公開では Firebase → DNS → デプロイの流れが多いです。

---

## Firebase まわり

- [ ] Google アカウントで **Firebase プロジェクト**を新規作成する
- [ ] **Web アプリ**を登録し、コンソールに表示された設定値を **`.env.local`** に転記する（キー名は `.env.example` を参照。実値は Git にコミットしない）
- [ ] 利用する機能に応じて、コンソールで **Firestore / Authentication** などを有効化する（九九アプリの学習データは **ブラウザの localStorage** に保存。Firebase Storage は使わない）
- [ ] ルートの **`.firebaserc`** 内 `your-firebase-project-id` を、実際の **プロジェクト ID** に書き換える
- [ ] ターミナルで `npx firebase login` を実行し、必要なら `npx firebase use <プロジェクトID>` でプロジェクトを切り替える
- [ ] Firebase Hosting を有効にし、**`npm run build`** のあと **`npx firebase deploy --only hosting`** でサイトを公開する
- [ ] `firestore.rules` を本番向けに編集したうえで、**`npm run firebase:deploy:rules`** でルールをデプロイする

---

## ムームードメイン（DNS）

- [ ] Firebase コンソール → Hosting → **カスタムドメインを追加**し、使うドメイン（例: `example.com` や `www.example.com`）を登録する
- [ ] 画面に表示される **DNS レコード**（TXT による所有権確認、A / AAAA など）をメモする
- [ ] **ムームードメイン**の DNS 設定画面で、種別・ホスト名・値を **Firebase の指示どおり**に入力して保存する  
  ※ ネームサーバーがムームードメイン以外の場合は、その事業者の DNS 管理画面で同様のレコードを追加する
- [ ] DNS の反映を待ち、Firebase コンソールで **ドメイン検証**と **SSL（証明書）のプロビジョニング**が完了したことを確認する

詳細な画面操作の例は、リポジトリ直下の `README.md` の「ムームードメインでの DNS 設定手順」を参照してください。

## GitHub → Firebase Hosting 自動デプロイ

- [ ] リポジトリに **`.github/workflows/firebase-hosting.yml`** をコミットする（本リポジトリに含まれています）
- [ ] [Google Cloud Console](https://console.cloud.google.com/) → IAM → サービスアカウント → **キーを追加（JSON）** で鍵を1つ作成する（または Firebase コンソール → プロジェクトの設定 → サービスアカウント）
- [ ] そのサービスアカウントに **Firebase Hosting 管理者**（`roles/firebasehosting.admin`）を付与する
- [ ] GitHub リポジトリ → **Settings → Secrets and variables → Actions** → **New repository secret**
  - 名前: `FIREBASE_SERVICE_ACCOUNT`
  - 値: ダウンロードした JSON ファイルの**中身全体**を貼り付け
- [ ] デフォルトブランチが **`main`** であることを確認する（`master` のみの場合はワークフローの `branches` を書き換える）
- [ ] `main` に push し、GitHub の **Actions** タブでワークフローが成功することを確認する

## PWA（ホーム画面アイコン）で中身が古いとき

- [ ] 問題やクイズを増やしたあとは、必ず **Hosting へデプロイ**する（push だけでは端末に届かない場合があります）
- [ ] スマホで一度アプリを開くと、新しい Service Worker が入り **自動で再読み込み**される想定です（`public/sw.js` の `SW_VERSION` を上げると確実です）
- [ ] それでも古いままのときは、ブラウザでサイトを開き **再読み込み**するか、ホーム画面のショートカットを削除して入れ直す

## 環境変数・リポジトリ運用

- [ ] **`.env.local`** を作成し、`NEXT_PUBLIC_*` などに実値を入れる（`.gitignore` によりコミット対象外）
- [ ] **CI** を使う場合は、パイプラインのシークレットに同じ環境変数名で値を登録する
- [ ] リモートの Git ホスティング（GitHub 等）を使う場合、**空のリポジトリを作成**し、`git remote add origin ...` で紐付けてから push する（ローカルでは `create-next-app` 実行時に `git init` 済みの場合があります）
